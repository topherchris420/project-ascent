The assistant uses deterministic property, pricing, offer and transaction evidence first. Models explain authorized evidence and draft text; they never calculate a valuation, set a contractual deadline, grant access, send a message or approve a professional action. One shared tool runner validates every argument, current source permission, citation ID, significant price/percentage and fair-housing output. Validation cannot prove that every generated statement follows from its citations; professional review remains required.

Groq is selected when GROQ_API_KEY is supplied. Routine explanations use `openai/gpt-oss-20b`; complex comparisons and assumption reviews use `openai/gpt-oss-120b`. These are listed production models. Published input/output estimates per million tokens are respectively $0.075/$0.30 and $0.15/$0.60; configured contract rates may override them. No local result establishes cost or latency superiority. Account model availability and rate limits require deployment verification. [Groq models](https://console.groq.com/docs/models)

Both selected models support strict JSON schemas. Groq currently prohibits combining Structured Outputs with tool use or streaming. The adapter therefore requests read-only tools first, then makes a separate nonstreamed strict-schema synthesis request. A question uses at most three provider rounds; tokens are metered independently. The SSE parser supports actual Groq content/tool deltas, but the application sends progress metadata and the validated final result to the browser. Unvalidated partial text and reasoning are never released. [Structured Outputs](https://console.groq.com/docs/structured-outputs), [tool calling](https://console.groq.com/docs/tool-use/overview), [streaming API](https://console.groq.com/docs/api-reference)

An explicit OPENAI_API_KEY plus OPENAI_MODEL preserves the existing Responses adapter when Groq is absent. With Groq configured, a deliberate secondary rerun requires AI_ALLOW_OPENAI_SECONDARY=approved and a request with provider=openai; it receives a fresh quota and budget reservation. No provider error silently escalates to another provider or model. Unknown Groq model IDs fail closed; optional models discovery intersects the local capability registry and cannot invent capabilities.

All licensed workspace sources currently block external model sharing, regardless of PII or billing flags. Known property/client/buyer names, contact details and stored free text are replaced by placeholders by default. Pattern redaction also removes recognized emails, phone numbers and identifiers. This is best effort: arbitrary sensitive question text cannot be guaranteed anonymous. AI_PII_SHARING=approved deliberately disables that optional redaction, but never disables the licensed-source block. No completed/private-text response cache is enabled, and no prompt, document, identity or model answer is written to inference telemetry. Account model metadata is cached for five minutes under a hashed credential identity. Identical concurrent allowlisted synthetic property/CMA/market questions may share one in-flight computation within the same tenant and evidence version; arbitrary questions, client/transaction contexts and non-synthetic sources are excluded. Reuse records zero additional provider tokens and cost. Set AI_INFLIGHT_DEDUP=false to disable it.

Groq’s Data Controls determine provider retention. Its policy permits reliability/abuse retention unless the organization enables the appropriate Zero Data Retention settings; ordinary app request flags do not change that account configuration. When AI_REQUIRE_ZDR=true, Ascent requires GROQ_ZDR_ATTESTED=approved and GROQ_ZDR_REVIEWED_AT with an operator review date before Groq calls. That is an operator assertion, not independent provider verification. Enable and inspect the actual organization/feature settings in Groq Console and review the contract before deployment. [Groq data controls and ZDR](https://console.groq.com/docs/your-data)

Groq and production requests require positive AI_DAILY_BUDGET_USD, AI_MONTHLY_BUDGET_USD and AI_REQUEST_BUDGET_USD. Reservations are atomic per tenant, independent of subscription quotas and professional/provider verification. Successful requests reconcile reported tokens against published/configured rates. Failed or incomplete transports keep their full reserved amount conservatively accounted; an administrator must reconcile that estimate against provider billing. A request is rejected before a call if its conservative input-byte/output-token envelope exceeds its cap. Provider-side spend limits remain a necessary independent control because app estimates cannot certify a provider invoice. Local legacy OpenAI development integrations retain their earlier quota-only compatibility when all budget fields are absent; production does not permit that exception.

The transport bounds context and output sizes, uses a 40-second question deadline, applies a configurable timeout up to 15 seconds per attempt, and retries only a 429 once. Retry-After values above two seconds or beyond the remaining deadline fall back to evidence instead of blocking a worker. Server errors and ambiguous transport failures are not automatically retried. [Groq rate-limit semantics](https://console.groq.com/docs/rate-limits)

GET /api/ai/status returns provider readiness, supported model capabilities, privacy attestation, budget windows, plan quota and configuration limitations. GET /api/ai/metrics returns only this tenant’s retained telemetry window (up to 500 events), token/cost estimates, latency, retries and outcomes. Both require an authenticated tenant session. POST /api/ai/discovery permits an authenticated owner to refresh account model metadata; discovery never adds unknown capabilities. POST /api/assistant preserves JSON responses by default and accepts stream=true for SSE, mode=evidence to avoid inference, and an explicitly approved provider override.

Run `npx tsx scripts/evaluate-ai.ts` for offline mocked fixtures across property Q&A, comparables, contracts, offers, uncertainty, missing live data and hallucination/safety rejection. The default path performs no network request; all nine offline fixtures passed. Live evaluation requires an explicitly supplied Groq key, AI_DATA_SHARING=approved, AI_EVAL_ALLOW_LIVE=approved, configured budgets, and `--live --max-usd=N`; do not run it without authorization to spend. The exclusive durable `evidence/ai-evaluation-spend.json` ledger reserves before each positive case; `--max-usd` is a cumulative ceiling that includes previous receipts, not a new allowance on each run. A crash retains its pending cap. Never remove the ledger to reset spend. Blocked positive paths fail the evaluation rather than counting as successful model tests; safety cases cannot issue a network request. Live artifacts retain only synthetic evaluation text and allowlisted provider diagnostics.

Actual live verification on October 15, 2026 (local time) was limited to two inference requests. The full assistant's 20B property-evidence request returned HTTP 400 in approximately 661 ms and fell back safely; its original error body was not retained, so the cause is unverified. No 120B inference or complete live final-answer workflow was verified. A separately authorized minimal 20B tool-phase diagnostic succeeded in approximately 463 ms, with 166 reported input tokens and 38 output tokens, yielding a configured-rate estimate of $0.00002385. It requested only the fictional `lookup_evidence` tool. Account metadata discovery returned both supported model IDs. The cumulative conservative authorization bound is $0.0099, which includes the failed request's full reserved amount; this is not a provider invoice. See `evidence/ai-evaluation.live.json` and `evidence/ai-evaluation.live-diagnostic.json`. These observations establish a working minimal transport/tool invocation and an unresolved full-assistant failure, not production inference reliability, factual accuracy, privacy-account verification, cost superiority or latency superiority.

The read-only `get_provider_evidence` tool reads only currently authorized normalized cached records or ZIP statistics. It never issues a provider lookup. Real provider cache entries independently block external model processing even when no source has been projected into the general workspace. Generic AI sharing approval cannot authorize RentCast or MLS AI use. Provider CMA context can be explained from its frozen input snapshot without creating a fabricated current listing or filling an unknown price, condition or days on market.
