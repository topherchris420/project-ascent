# Client search and follow-up continuity

The existing Clients workspace now supports structured minimum bedrooms/bathrooms/living area, a price ceiling, literal address/city/state/ZIP query, state/ZIP restrictions and listing status. Legacy searches default to active inventory. `evaluateSavedSearch` applies the same deterministic filters across supported markets; it does not interpret demographics, estimate a buyer's preferences or ask an LLM to rank housing.

Every match exposes satisfied constraints. Exclusions identify failed criteria, and incomplete records remain unresolved rather than being filled with guesses. These checks consume only currently authorized **stored workspace inventory**. Full RentCast research records remain separate until a complete listing can be admitted through the existing national fabric; no listing status, asking price or condition is manufactured to make a property eligible.

An agent explicitly reviews a saved search to create source-backed in-app alerts. A stable fingerprint includes criteria and property facts; unchanged reviews create no duplicate alerts. No provider refresh, message, email or external action is triggered. Saving a property for a client preserves the relationship. Applied saved-search filters in the property explorer include the price and structural criteria, rather than just redisplaying the location string.

Follow-up tasks record a human-selected title and date. Agents can complete and reopen them; completion adds a relationship timeline event. These are reminders, not inferred contractual obligations. Tasks, saved criteria and alerts connect to the decision graph. Permission-filtered JSON export retains the new fields, while CSV contact export stays within its documented contact format. Aggregate task metrics are recorded only when the existing product-analytics consent is enabled.

The same viewer restrictions, tenant-bound persistence, input/date validation, Fair Housing triage and current-source scoping apply. Searches are inspected both when saved and when reviewed, so an imported or older unsafe query cannot bypass the workflow gate. Revoked property evidence removes associated follow-ups and alerts from authorized read views. Free text is conservatively withheld alongside other client context when a source becomes unavailable.

Acceptance covers deterministic filtering, missing data, geography, source-linked deduplication, private persistence, complete/reopen behavior, viewer/cross-tenant denial, invalid dates, unsafe text, revoked evidence and browser reload continuity. These are authored synthetic tests, not a study of professional relevance, outreach usefulness or time saved. Phone/role-rich profiles, property-type/neighborhood geometry filters, live inventory synchronization and notification delivery remain future work.
