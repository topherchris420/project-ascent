# RentCast provider transport

`src/lib/providers/property-provider.ts` defines the normalized server interface; `rentcast.ts` implements it. `fixture-property.ts` implements the same interface without network access. Fixtures are invented software examples, with provenance `dataKind: synthetic`. They do not demonstrate coverage, market accuracy, or a live connection. Address lookup is exact; an unrelated address never receives the sample subject.

The real adapter uses only `https://api.rentcast.io/v1` and these four GET endpoints:

| Method | Endpoint | Interpretation |
| --- | --- | --- |
| getProperty, searchProperties | /properties | Property facts and provider-recorded sale history |
| getSaleListings | /listings/sale | Asking prices and active/inactive listings |
| getComparables, getValuation | /avm/value | Provider AVM and its selected sale listings |
| getMarketStatistics | /markets | ZIP aggregate active sale-listing statistics |
| getCoverage | No request | Documented coverage limitations, unverified connection |

`getValuation` already returns its comparable listings. Calling `getComparables` separately issues another AVM request; callers should reuse the first response. Inactive listings are not closed sales. The AVM's selected comparable prices are asking prices. Only property-record sale fields become `recorded-sale` objects. Missing fields remain missing; no inspected condition, sale concession, closing date, or real outcome is synthesized. [Property schema](https://developers.rentcast.io/reference/property-data-schema), [valuation schema](https://developers.rentcast.io/reference/property-valuation-schema), [listing schema](https://developers.rentcast.io/reference/property-listings-schema).

The normalized DTO retains optional assessments, taxes and historical sale-listing snapshots. Historical listing snapshots do not establish an exhaustive history of every within-listing price change. Market statistics retain provider update dates and distinguish asking-price aggregates from closed transactions; they do not establish absorption, closed-sale inventory or mortgage rates. The provider describes the AVM interval as 85% coverage; this application labels that statement as a provider claim and has not calibrated it. [Market schema](https://developers.rentcast.io/reference/market-data-schema), [valuation schema](https://developers.rentcast.io/reference/property-valuation-schema).

Set server-only `RENTCAST_API_KEY`. Optional `RENTCAST_TIMEOUT_MS` defaults to 8000 and is clamped to 100–15000 milliseconds. No browser key is accepted. The client refuses browser construction, stores the key in a JavaScript private field, prohibits redirects, and disables framework HTTP caching. It always sends `Accept: application/json`, `X-Api-Key`, and **query parameter** `suppressLogging=true`. RentCast documents this parameter as suppressing storage of submitted request parameters; this does not assert elimination of all operational metadata or alter other contractual retention. Configure endpoint/IP key restrictions in the provider dashboard where appropriate. [Security documentation](https://developers.rentcast.io/reference/security).

Each operation makes at most one request. There are **zero automatic retries**, including 429, 5xx, timeouts and connection failures, because an attempted provider operation may be billable. Errors expose only a stable code, HTTP status and bounded numeric Retry-After, never a raw provider body, key, query or address. Application-managed reservations remain conservative after a failed attempt. Pagination is explicit, limited to 100 results per page and offset 10000; the application service may impose tighter limits. `X-Total-Count` is used when available; otherwise `hasMore` is labeled an estimate. No automatic pagination or paid health probe occurs. [Pagination](https://developers.rentcast.io/reference/pagination), [response codes](https://developers.rentcast.io/reference/response-codes).

Strict input validation requires a bounded geographic selector, complete coordinate/radius queries, supported property types and valid numeric bounds. Valuation comparable count is explicitly 5–25. Responses are streamed into a 4 MiB bound, parsed with field schemas and normalized using an allowlist. Owner names, owner occupancy, owner mailing addresses, listing contacts, offices and builder contacts are discarded rather than persisted or logged. The client does not log requests or responses. It does not itself authorize a user or grant data rights; every production caller must use the application service's tenant authorization, independently reviewed contract/use grants, retention, metering, concurrency, cache and budget gates. No live request should be initiated simply because a key exists. [Value estimate query](https://developers.rentcast.io/reference/value-estimate), [API terms](https://www.rentcast.io/terms-api).

API terms and account permissions require professional/legal review for the intended use. A paid application plan supplies neither provider rights nor professional licensure. Retained provider evidence is denied external AI processing by default; a general AI-sharing flag supplies no contracted AI-use permission. No real provider key or paid request was used for the transport acceptance tests. Nine mocked tests validate URLs, query validation, minimization, price semantics, paging, errors and timeout behavior. Live response behavior, actual provider latency, billing, coverage and forecast accuracy remain unmeasured.
